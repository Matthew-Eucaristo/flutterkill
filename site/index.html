Flutter projects grow quietly.
Take the space back, Trash first.

Every project keeps build/, .dart_tool/, CocoaPods and Gradle state, and the machine collects a pub cache, Gradle downloads, old FVM SDKs and Xcode caches. flutterkill finds all of it, shows which projects you haven't touched in months, and moves what you pick to the Trash. Like npkill, but it knows Flutter.

$ brew install matthew-eucaristo/tap/flutterkill

Then run flutterkill. Nervous? flutterkill --dry-run changes nothing. Other ways to install →

Inside every project

Only what sits next to a pubspec.yaml.

Projects are found by their pubspec.yaml, and only directories at a known place next to it are offered. A folder called build anywhere else is never touched, and your code never shows up at all.

Staleness at a glance

The project you shipped a year ago stands out.

Each project shows its last activity: the latest commit or uncommitted change, so gitignored build output doesn't count, or file times outside git.

  • Yellow after six months, green within the last 30 days. o sorts by size, oldest activity or name.
  • A filter for scripts: --older-than 6mo keeps only projects untouched that long (90d, 6w, 1y work too).
  • Read-only git. Queries run with optional locks and fsmonitor off, so flutterkill does not even refresh a project's index.

Machine-wide caches

The space no single project owns.

Shown only if present. Every project shares them, so they are marked ▲ caution and live in their own tab. You pick them yourself; --yes never touches them. Settings, plugins, the Android SDK, Flutter SDK checkouts and emulator images are installs, not caches, and are never listed.

Safety model

A guard checks every path, right before it goes.

However an item was found, internal/clean/guard.go checks it again immediately before removal. All removal code lives in internal/clean.

⌖Known places only

An artifact must be one of the fixed paths, in a project inside the scanned root that is not your home folder, that still has its pubspec.yaml, and it must be a real directory.

⎇Never real work

Refused if it holds a pubspec.yaml or .git directly, or any file tracked by git. Generated output is never committed.

↯No symlinks

No path component between the root and the artifact may be a symlink, and nothing is followed while measuring or deleting.

▤A fixed cache catalog

Caches must be in the catalog in internal/caches. /, top-level folders and your home are refused, even when PUB_CACHE or GRADLE_USER_HOME point there.

⌘Two commands, in red

Only dart pub cache clean --force and xcrun simctl delete unavailable. They delete by design, so the confirmation marks them red.

☰You see what goes

The y/N prompt lists every item. A delete only reaches items in the tab you are looking at.

⌫Trash by default

macOS Trash, the freedesktop home trash on Linux, the Recycle Bin on Windows. --permanent is opt-in. One removal at a time; ctrl+c lets the running one finish.

◌Read-only modes

--dry-run runs every check and changes nothing. --list, --json and scan --json never remove anything.

The receipt

Moved, deleted and delegated. Never added together.

Moving to the Trash frees nothing until you empty it, so flutterkill does not pretend it did. On exit it prints one line per item, then a total for each kind of removal with the change in free disk space, measured before and after.

after q, from the recorded demo
$ flutterkill
trashed          9.4 MB  ~/dev/archive/legacy_app/.dart_tool
trashed         29.4 MB  ~/dev/archive/legacy_app/build
Moved about 38.8 MB to the Trash (free space changed by -32.8 kB, measured). Empty the Trash to reclaim it.
$ █
  • Trashed: restorable. The space comes back when you empty the Trash.
  • Deleted: with --permanent only.
  • Delegated: the owner's own clean-up command ran, and it deletes.

The family

Works alone. Also speaks decruft.

flutterkill speaks the same versioned machine contract as fell and nodekill. A caller such as decruft never deletes paths itself: it sends back {id, fingerprint} pairs, and flutterkill scans again, refuses anything that changed and runs its own guards.

# what this build can do
flutterkill capabilities --json
# items with ids, fingerprints and safety reasons (read-only)
flutterkill scan --json [--no-global] [root...]
# act on ids + fingerprints; consent comes only from flags
flutterkill apply --plan - [--dry-run] [--permanent] [--json]
  • Pinned to what you saw. Each item's fingerprint covers its path, directory identity, level, reasons and action. A changed item is refused as stale.
  • No usernames in output. Paths under home are written as ~/….
  • Same judgement everywhere. ● safe in the TUI is safe in the contract and ▲ caution is review, so decruft shows what flutterkill would.

Use

A TUI when you look. A table or JSON when you don't.

Pipes and redirects get the plain table, never the TUI. --json prints the scan, and --yes cleans every artifact of the matched projects without asking, never global caches.

# scan ~/dev, or the current folder without one
flutterkill
# another root
flutterkill ~/code
# try everything, remove nothing
flutterkill --dry-run
# only projects untouched for 6 months
flutterkill --older-than 6mo
# plain table; JSON; both read-only
flutterkill --list
flutterkill --json
# preview a non-interactive clean, then run it
flutterkill --older-than 1y --yes --dry-run
flutterkill --older-than 1y --yes
# delete instead of the Trash (opt-in)
flutterkill --permanent

Install

One binary. Nothing left behind.

$brew install matthew-eucaristo/tap/flutterkill

macOS and Linux. Homebrew builds it from source.

$go install github.com/Matthew-Eucaristo/flutterkill@latest

Go 1.26 or later, on any OS including Windows.

Download from GitHub Releases →

Archives for macOS, Linux and Windows on amd64 and arm64. On Windows, unzip flutterkill.exe into a folder on your PATH and run it in Windows Terminal or PowerShell.

macOSThe Trash through /usr/bin/trash on macOS 15+, Finder on older versions. Xcode, CocoaPods and SwiftPM caches join the list.
LinuxThe freedesktop.org home trash. Moves across filesystems are refused rather than copied.
WindowsThe Recycle Bin. Drives without one and paths of 260+ characters are refused; use --permanent there.
Uninstalling leaves nothing behind 
brew uninstall flutterkill
brew autoremove                    # removes Go if it was installed only to build flutterkill
brew untap matthew-eucaristo/tap   # only if nothing else is installed from this tap

flutterkill writes no config, cache, log or state files and makes no network requests. With go install: rm "$(go env GOPATH)/bin/flutterkill". Anything you moved to the Trash stays there until you empty or restore it.

Questions

Fair questions.

Isn't this just flutter clean in a loop?

No. flutter clean leaves CocoaPods behind, knows nothing about the pub, Gradle, FVM or Xcode caches, cannot tell which project you abandoned a year ago, and deletes instead of using the Trash. flutterkill covers all four.

Will it delete my Flutter SDK or Android SDK?

No. The Android SDK, Flutter SDK checkouts and emulator images are installs, not caches, and are deliberately not on the list. FVM's cached SDK versions are listed, one row per version, with the scanned projects that pin each one.

Why are global caches marked caution?

Because every project shares them, a scanned project may pin one (an FVM SDK, a Gradle version), and the pub cache is cleaned by dart pub cache clean --force, which cannot be undone. They come back, but the next build is slower. You can still pick them in the Global caches tab; --yes never reaches them.

I removed 2 GB. Why is my disk not 2 GB emptier?

Because it is in the Trash, where you can put it back. The receipt says so and shows the change in free space it measured, instead of the size it hoped for. Empty the Trash to reclaim it.

Does it phone home or keep state?

No. No config, cache, log or state files, and no network requests. On Linux, the first move creates the standard ~/.local/share/Trash folders if they are missing. This page loads nothing from third parties either.

Can I script it?

Yes: --list for a table, --json for the scan, --older-than 1y --yes to trash every artifact of year-old projects (never global caches), and the machine contract for tools that build on it.

I found a bug that touches the wrong thing.

That is a security issue. Please report it privately through GitHub Security Advisories, not a public issue.
