# flutterkill machine contract (schema_version 1)

flutterkill uses the same envelope as the other tools of the family (`fell`, `nodekill`), so an umbrella such as `decruft` can show what flutterkill sees and hand removals back to it without bypassing its checks.

## Principles

1. **The tool that knows the domain does the removal.** A caller never deletes paths from a scan; it hands a plan back, and flutterkill scans again and re-applies its own rules and guards.
2. **Plans are pinned to what the user saw.** Each item carries a `fingerprint` of its safety-relevant state (path, directory identity, level, reasons, action, command). If it changed, the item is refused as stale.
3. **No usernames in output.** Paths under home are written as `~/…`.
4. **Additive evolution.** Within a schema version, fields, reason codes and exit codes may be added but never renamed, removed or repurposed. Consumers ignore unknown fields.

The older `flutterkill --json` output (projects and caches, no ids) is unchanged and is not part of this contract.

## Discovery: `flutterkill capabilities --json`

Returns `schema_version`, `tool {name: "flutterkill", version, ecosystem: "flutter"}`, `commands`, `actions` (`trash`, `delete`, `command`), `categories` (`project`, `cache`, `runtime`), `safety_levels` (`safe`, `review`, `protected`, `live`), `reason_codes` (`{code, level, effect}`), `artifact_kinds` and `cache_kinds` (`{kind, level, owner, regenerate}`), `exit_codes` and the OS's name for the trash.

## Scan: `flutterkill scan --json [--no-global] [root...]`

Read-only. Roots default to `~/dev`, else the current directory. Unless `--no-global`, machine-wide caches (pub cache, Gradle, FVM versions, old Android Studio caches, Xcode caches, unavailable simulators) are included, listed once even with several roots.

```json
{
  "schema_version": 1,
  "tool": { "name": "flutterkill", "version": "0.3.0", "ecosystem": "flutter" },
  "generated_at": "2026-10-27T05:00:00Z",
  "roots": ["~/dev"],
  "warnings": [],
  "size_note": "allocated blocks like du; …",
  "summary": {
    "items": 2, "projects": 1,
    "bytes": { "allocated": 1200000000, "shared": 0, "exclusive": 1200000000, "file_count": 0 },
    "safe_bytes": { "allocated": 412000000, "shared": 0, "exclusive": 412000000, "file_count": 0 },
    "by_safety_level": { "safe": 1, "review": 1 },
    "by_category": { "project": 1, "cache": 1 }
  },
  "items": [
    {
      "id": "art-3f9c0e1d2a4b", "fingerprint": "fp-7bc4c3f502b81124",
      "kind": "build", "category": "project", "name": "build", "path": "~/dev/my_app/build",
      "project": { "path": "~/dev/my_app", "name": "my_app", "flutter": true, "fvm_version": "3.24.5",
                   "last_activity": { "at": "2026-08-02T10:14:03Z", "source": "git", "age_days": 86 } },
      "action": "trash", "regenerate": "the next flutter build or flutter run",
      "explain": "Flutter build output for every platform.",
      "measured": true, "bytes": { "allocated": 412000000, "shared": 0, "exclusive": 412000000, "file_count": 0 },
      "safety": { "level": "safe", "reasons": [{ "code": "generated", "level": "safe", "detail": "regenerated by the next flutter build or flutter run" }] }
    },
    {
      "id": "glb-c3b2697505d2", "fingerprint": "fp-e6c0a17ed82662e3",
      "kind": "pub-cache", "category": "cache", "name": "Pub cache", "path": "~/.pub-cache", "project": null,
      "tool": "Dart", "action": "command", "command": ["dart", "pub", "cache", "clean", "--force"],
      "regenerate": "the next pub get", "explain": "Downloaded Dart/Flutter packages. …",
      "measured": true, "bytes": { "allocated": 788000000, "shared": 0, "exclusive": 788000000, "file_count": 0 },
      "safety": { "level": "review", "reasons": [
        { "code": "global_cache", "level": "review", "detail": "shared by every project on this machine" },
        { "code": "deletes", "level": "review", "detail": "`dart pub cache clean --force` deletes; it does not use the trash" } ] }
    }
  ]
}
```

| Field | Meaning |
| --- | --- |
| `id` | Stable id: `art-…` for a project artifact, `glb-…` for a machine-wide item. Use it in plans. |
| `fingerprint` | Hash of the safety-relevant state. Sizes and times are left out, so a build writing into `build/` does not invalidate a plan. For a command it also covers the folders the command removes. |
| `kind` | An artifact's position next to `pubspec.yaml` (`build`, `.dart_tool`, `ios/Pods`, …) or a cache kind (`pub-cache`, `dart-server`, `gradle-caches`, `gradle-jdks`, `gradle-dist`, `android-studio`, `fvm`, `xcode-derived-data`, `xcode-device-support`, `cocoapods-cache`, `swiftpm-cache`, `simulator-caches`, `simulators-unavailable`). |
| `category` | `project`, `cache`, or `runtime` (FVM Flutter versions, Gradle wrapper distributions). |
| `project` | For artifacts: `{path, name, flutter, fvm_version, last_activity}`; `null` otherwise. |
| `tool` | Owner of a machine-wide item (`Dart`, `Gradle`, `Xcode`, …). |
| `action`, `command` | `trash` (moved to the trash; deleted with `--permanent`) or `command` (the owner's clean-up, which deletes by design) with its exact argv. |
| `used_by` | Scanned projects that use an FVM or Gradle version. |
| `measured`, `bytes` | `{allocated, shared, exclusive, file_count}`. flutterkill counts allocated blocks like `du` and hard links once; it does not separate APFS clone blocks, so `exclusive` equals `allocated` and `shared` is 0. `file_count` is not counted (0). |
| `safety` | `{level, reasons[{code, level, detail}]}`. |

### Levels and reason codes

| Level | Meaning |
| --- | --- |
| `safe` | Generated and regenerable; may be bulk-selected. Every project artifact. |
| `review` | Allowed when chosen explicitly (a plan), never in bulk. Every machine-wide item. |
| `protected`, `live` | Never acted on. Reserved; flutterkill 0.3 leaves out what its guards refuse instead of listing it. |

Codes: `generated` (safe), `global_cache`, `used_by_projects`, `deletes` (review).

## Plan and apply: `flutterkill apply --plan <file|-> [--dry-run] [--permanent] [--json] [root...]`

```json
{ "schema_version": 1, "items": [ { "id": "art-3f9c0e1d2a4b", "fingerprint": "fp-7bc4c3f502b81124" } ] }
```

- Unknown fields are rejected, so a plan cannot smuggle options; consent comes only from flags on the command line.
- Pass the same roots as the scan. Caches are discovered only when the plan names a `glb-` item.
- Items run one at a time: fresh scan, fingerprint check, level check, flutterkill's guards (the same ones its TUI uses: position next to `pubspec.yaml`, no symlinks, no git-tracked files, only catalogued caches and commands), then the action. The guards run once more right before removal.
- The first `SIGINT` stops before the next item; items not reached are refused with `interrupted`.

### Result (`--json`)

```json
{
  "schema_version": 1,
  "tool": { "name": "flutterkill", "version": "0.3.0", "ecosystem": "flutter" },
  "mode": "trash",
  "results": [
    { "id": "art-3f9c0e1d2a4b", "kind": "build", "action": "trash", "path": "~/dev/my_app/build", "status": "done",
      "estimated_bytes": 412000000, "freed_bytes_measured": 0,
      "restore_hint": "restore from the Trash, or let the next flutter build or flutter run recreate it" }
  ],
  "summary": { "done": 1, "dry_run": 0, "refused": 0, "failed": 0, "trashed_bytes": 412000000,
               "command_bytes": 0, "deleted_bytes": 0, "estimated_bytes": 412000000, "freed_bytes_measured": 0 }
}
```

- `status`: `done`, `dry_run`, `refused` (nothing changed; `reasons` is one of `stale`, `gone`, `guard`, `interrupted` or the item's level, and `error` says why), `failed` (an error after the checks passed).
- `action`: `trash`, `delete` (a trash item with `--permanent`) or `command`.
- `estimated_bytes` is the item's size measured just before acting; `freed_bytes_measured` is the measured change in free space (`-1` unknown). After a move to the trash it stays near zero until the trash is emptied.

Without `--json`, apply prints one line per item and a total.

### Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Every item done (or dry run). |
| 1 | Error before acting. |
| 2 | Usage error (bad flags, invalid plan). |
| 3 | At least one item refused, none failed. |
| 4 | At least one item failed. |
